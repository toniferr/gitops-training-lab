# Reference: `cac-gitops-platform`

Canonical repository: `https://github.com/toniferr/cac-gitops-platform`.

## Responsibility

This repository is the desired state entry point for a cluster. Flux bootstraps here, reads `clusters/kind-dev`, creates the `java-api` namespace, fetches the Java application source, and applies its manifests.

## `clusters/kind-dev/kustomization.yaml`

The root [Kustomize](https://kustomize.io/) file lists four resource groups:

| Resource | Meaning |
| --- | --- |
| `flux-system` | Flux-generated controllers plus local Flux source definitions. |
| `../../infrastructure/namespaces` | Shared Namespace objects, including `java-api`. |
| `infrastructure` | Cluster-specific infrastructure extension point. |
| `apps` | Flux Kustomizations for workloads selected for this cluster. |

Kustomize does not deploy an application by itself here. It assembles this directory so Flux can apply it as the cluster's declared state.

## `clusters/kind-dev/flux-system/gotk-sync.yaml`

This file is generated by `flux bootstrap github`; do not edit it by hand. Its [`GitRepository`](https://fluxcd.io/flux/components/source/gitrepositories/)`/flux-system` records the platform Git URL and branch. Its [`Kustomization`](https://fluxcd.io/flux/components/kustomize/kustomizations/)`/flux-system` reads `./clusters/kind-dev`, which starts the chain above.

## `clusters/kind-dev/flux-system/apps-source.yaml`

`GitRepository/java-api` tells Flux source-controller to clone `java-api-gitops` every minute. The URL is the application source; `ref.branch` selects the exact app branch used by the training. A private application repository requires suitable read credentials for this source.

## `clusters/kind-dev/apps/java-api.yaml`

This Flux `Kustomization` says: obtain the source named `java-api`, build `./k8s`, apply it in namespace `java-api`, wait for readiness, and remove objects no longer declared because `prune` is true. Its five-minute interval is the normal reconciliation period; the CLI can force a reconciliation during a demo.

## `infrastructure/namespaces/java-api.yaml`

This is an ordinary Kubernetes [Namespace](https://kubernetes.io/docs/concepts/overview/working-with-objects/namespaces/). It must exist before a namespaced workload can be created. Keep environment- or cluster-level primitives in platform rather than application repositories.

## Training branch adaptation

For a training branch, change both the platform bootstrap source and the Java `GitRepository` ref to `training/01-gitops-flux-foundations`. That pins the exercise to matching versions of platform and application.

Working from your own fork? Also change `apps-source.yaml`'s `url` to your own `java-api-gitops` fork — the `ref.branch` change alone still reads from wherever `url` points. Forgetting this is the single most common way this exercise silently fails: your commits go to your fork, but the cluster keeps reconciling against the original repository.
